## Decisions

- **The prompt runs `uvx prepush-ci skill`.** The reader may have nothing installed yet, and `uvx` runs the command without installing; the skill it prints is the one of the version run (`skill-command`: no repository, no network). Rationale: it is the sentence #138 was built for.
- **The project-skill way is `prepush-ci skill --write`, not copying `skills/prepush-ci-setup/`.** A reader from PyPI has no checkout to copy from; `--write` puts the file where the folder copy did. Rationale: the folder copy cannot be followed by the reader this change is for.
- **The plugin commands are pinned by the manifests.** The README names the marketplace `prepush-ci` and the plugin `prepush-ci`, so a spec compares `prepush-ci@prepush-ci` with `.claude-plugin/marketplace.json`; a rename there fails the README spec. Rationale: AGENTS.md, "Docs say only what is pinned or run".
- **The slash commands are code spans, the prompt stays the only code block of the step.** The existing helper of the README spec reads the step's single block as the prompt. Rationale: no second block to reconcile.
- **A form that runs before the release.** PyPI has only 0.0.0 without the `skill` command, and the release waits for this change, so the step also gives `uvx --from git+https://github.com/CapeOfGoodCode/prepush-ci prepush-ci skill` under the words step 2 already uses, "until the first release is on PyPI". Rationale: blocking on the release would wait on itself; the form is pinned by `skill-command` and the command check.
- **A new requirement replaces the old.** The old one pinned the link; it is REMOVED and "The agent step hands the agent the skill command" is ADDED, so no scenario says the opposite of its name. The walk requirement drops the pointer "(previous requirement)", which no longer points at it.
