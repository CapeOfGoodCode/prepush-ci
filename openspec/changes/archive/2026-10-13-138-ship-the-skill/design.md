## Decisions

- **The command is `skill`, with one option `--write`.** `prepush-ci skill` reads like the thing the agent is told to run, and a single option keeps the surface small: no `--path`, no `--force`. The target is fixed, the project-skill path Claude Code reads.
- **`--write` replaces the file.** The file in `.claude/skills/` is a generated copy of the tool's skill; a rerun after an upgrade should bring it up to date, and git shows what changed. It reports `wrote` either way.
- **The skill goes into the wheel as package data (`[tool.uv.build-backend.data] data = "skills"`), found through the distribution's file list.** It keeps `skills/prepush-ci-setup/SKILL.md` the only source (the plugin needs it at the repository root) and keeps `uv_build`; the alternative, moving the file into `src/prepush_ci/`, would change every spec and the README that name its path, and a symlink breaks on Windows checkouts. The cost is the install location: the installer puts the file in the environment's data directory (`<prefix>/prepush-ci-setup/SKILL.md`), not in the package. `importlib.metadata` records the installed path in the distribution's `RECORD`, so the command locates it with `distribution("prepush-ci").files` and does not guess the prefix.
- **A source checkout is read first, the installed data second.** When `skills/prepush-ci-setup/SKILL.md` exists two directories above the package (`src/prepush_ci/../../skills/…`), the command reads it: in a checkout (an editable install, the test suite) that is the file being edited, never a copy that `uv sync` made once. In a wheel install that path does not exist, and the distribution's data file is read. Neither found: exit 1 with a message.
- **Bytes, not text.** The file is written to standard output and to the target through binary I/O, so no newline translation on Windows can make the packaged skill differ from the file in the repository.
- **The plugin is the repository root, not a subdirectory.** A plugin's `skills/` directory is found at its root by default, and the repository root already has `skills/prepush-ci-setup/SKILL.md`. A plugin in a subdirectory (`plugins/prepush-ci/`) would need a copy or a symlink of the skill. The cost is that Claude Code caches the whole repository for the plugin; only the skill is a component of it.
- **The manifests live in `.claude-plugin/`, not `.claude/`.** `LOOP.md` reserves `.claude/` (hooks and skills for the agents that work on this repository); `.claude-plugin/` is the directory Claude Code reads a plugin and its marketplace from, and holds nothing for those agents.
- **The plugin and the marketplace are both named `prepush-ci`, and `plugin.json` has no `version`.** The version of the project lives only in `pyproject.toml` (`AGENTS.md`); a second one would drift. Claude Code then versions the plugin by commit. The consequence is that the plugin follows the default branch, as the URL did, while `prepush-ci skill` is the way to get the skill of the exact installed version; the README (#139) says so.
- **The wheel is checked by building it as the release does.** `uv build` makes the sdist and then the wheel from it, so a skill left out of the sdist would be missing from the wheel. The spec installs that wheel into a new virtual environment and runs the installed command; nothing smaller proves the lookup through `RECORD`.
- **`claude plugin validate` is not part of the suite.** CI has no Claude Code. The spec checks the facts that command checks and a plugin needs (names, the source, the skill's front matter); the run below was done once by hand.

## Tools run

uv 0.13.0 (the build requirement `uv_build>=0.8,<0.13` resolves in the isolated build), `pyproject.toml` with the two lines `[tool.uv.build-backend.data]` and `data = "skills"`, on a copy of the repository:

- `uv build` builds the sdist, then `Building wheel from source distribution...`. The sdist lists `prepush_ci-0.0.0/skills/prepush-ci-setup/SKILL.md`; the wheel lists `prepush_ci-0.0.0.data/data/prepush-ci-setup/SKILL.md` and nothing else new.
- Installed with `uv pip install` into a new `uv venv`, `distribution("prepush-ci").files` has the entry `../../../prepush-ci-setup/SKILL.md` and `.locate()` gives `<venv>/prepush-ci-setup/SKILL.md`, which exists.

Claude Code 2.1.296, a copy of the repository with `.claude-plugin/plugin.json` (name, description, author, homepage, repository, license), `.claude-plugin/marketplace.json` (name, owner, one plugin with `"source": "./"`) and `skills/prepush-ci-setup/SKILL.md`, committed in a throwaway git repository, `CLAUDE_CONFIG_DIR` set to an empty directory:

- `claude plugin validate .` exits 0; its only warnings are the missing `version` (kept on purpose) and a missing marketplace description.
- `claude plugin marketplace add <path>` then `claude plugin install prepush-ci@prepush-ci` succeed; `claude plugin details prepush-ci` lists `Skills (1)  prepush-ci-setup` and no other component.
