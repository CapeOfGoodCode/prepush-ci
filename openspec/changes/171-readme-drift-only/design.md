## Decisions

- **The README-only pre-release ban goes with the rest.** #171 lists "The README says nothing of an unreleased state" (added by #168) among the prose. A leftover "under construction" is README text, so from now on its removal is a `Task` with a `docs:` commit, as AGENTS.md says. Rationale: the issue names it; the cost is that nothing fails if that wording creeps back, which the review of a README `Task` has to catch.
- **The agent step stays as the place the three kept checks read, and the spec defines it.** The prompt's command, the missing link to `SKILL.md` and the plugin commands are checked in the usage step whose heading names the agent, as the tests find it today; the first new requirement says the usage section SHALL have such a step. Rationale: scanning the whole README instead would rewrite three tests, which the issue does not ask. The step is structure the checks need, not prose they pin. A README-wide scan is not part of this change and no follow-up is filed: it is the boundary of what #171 asks.
- **The plugin requirement stays whole.** #171 lists "names the Claude Code plugin" under "These stay as they are", and its table removes no scenario of it; so "The plugin way" (the spans `/plugin marketplace add CapeOfGoodCode/prepush-ci` and `/plugin install prepush-ci@prepush-ci`) and "The plugin commands match the manifests" stay, and a README that drops the install span still fails. Rationale: follow the issue; the cost is that the spans' wording stays pinned.
- **This change adds one test, against "no other test changes".** The scenario "The agent step exists" has a test, and `agent_step` reports a problem instead of raising `StopIteration` when no step names the agent. This departs from the acceptance criterion "no other test changes". Rationale: spec review found that the kept checks depended on a step the spec no longer defined; defining it without testing it would leave a SHALL with no test.
- **The prompt scenarios drop the words of the prompt and its place.** "A prompt to hand over" pinned `follow` and the ask to set the repository up; the kept scenario requires only the invocation `prepush-ci skill` in the one code block of the agent step and no command or option the CLI lacks. Rationale: the invocation is what can drift; the sentence around it is wording.
- **The Purpose is edited in the spec, not in a delta, and its words are fixed here.** OpenSpec deltas cover requirements only, so the builder replaces the Purpose paragraph of `openspec/specs/readme/spec.md` in the implementation commit with the text below, word for word (task 1.5); spec review reads it here.

  > What `README.md`, the PyPI long description, says a user acts on, and the checks that keep it true against the CLI and the config: every command and option exists, the reference leaves none out, the keys and defaults are the config's, and the agent step's prompt and plugin commands match the CLI and the manifests. The spec checks drift, not prose.

- **Three tests have no scenario today and stay.** `test_the_reference_names_the_commands_that_exit_two_on_a_wrong_command_line`, `test_the_usage_step_on_strip_names_its_range_and_the_force_push` and `test_the_entry_of_strip_names_the_force_push` test README prose that no `readme` requirement covers; the issue says "no other test changes", so they stay and are not part of this change. Their deletion is filed as #187 (a `Task`, blocked by #171).
